# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Dancing Dead Dystopia" (the repo directory is spelled `dead-dancing-distopia`): a mobile, portrait-orientation 2D game built with **Godot 4.7** using GDScript. The UI text is in Spanish (`JUGAR`, `CONFIGURACION`, `SALIR`), so keep any new player-facing strings in Spanish.

## Commands

Godot is installed at `/usr/bin/godot`. There is no build system, linter, or test suite.

```bash
godot --editor --path .                          # open in editor
godot --path . res://menu/screen_main_menu.tscn  # run starting from the main menu
godot --path . res://game/gameplay_scene.tscn    # run a specific scene
godot --headless --path . --import               # re-import assets / regenerate .godot/ cache
godot --headless --path . --check-only --script res://path/to/file.gd   # parse-check one script
godot --headless --path . -s res://tools/midi_to_chart.gd -- Assets/Songs/<id>   # lead.mid -> chart.json
godot --headless --path . -s res://tools/midi_to_chart.gd -- --all               # every song with a lead.mid
~/transcribe-env/bin/python tools/audio_to_lead_mid.py Assets/Songs/<id>           # lead audio -> lead.mid (no MIDI available)
```

`audio_to_lead_mid.py` is for songs that don't have a MIDI. It measures a fixed tempo and the first beat's phase from the backing track (and warns if a section drifts more than 40 ms, i.e. the tempo isn't fixed), then aligns the grid to the start of the drum attacks rather than their detection peak, which is about 20 ms later and makes notes feel late. It transcribes the `lead` stem with basic-pitch and drops notes where the stem is near silent (Demucs bleed). It splits notes at every vocal attack inside them: basic-pitch merges same-pitch syllables, so rap would otherwise become one long note. It moves each note start to its syllable's attack, and adds loud, separated attacks that basic-pitch didn't transcribe, using the nearest note's pitch. Finally it compensates the average onset lag and snaps each beat to sixteenths, or to triplets only when they clearly fit better. `--min-gap` thins the notes for easier songs. It needs the `~/transcribe-env` venv (setup in the script's docstring: basic-pitch is installed `--no-deps` because its TensorFlow pin has no Python 3.14 wheels, and it runs the ONNX model through onnxruntime; `setuptools<81` is needed for `pkg_resources`). Always run `midi_to_chart.gd` afterwards.

Re-run the converter after changing a `lead.mid` or the mapping rules in `chart_mapper.gd`; the generated `chart.json` files are not updated automatically.

`run/main_scene` is `menu/screen_main_menu.tscn` (referenced by UID), so `godot --path .` (or F5) starts at the menu.

The Godot MCP server (`mcp__godot__*`) may be available for launching or running the project, reading debug output, and creating or editing scenes.

## Display / platform settings

These settings constrain all UI and layout work:
- The design resolution is **1080×1920** (portrait), but the desktop window is overridden to 360×640 for testing. Use stretch mode `canvas_items` with aspect `expand`. Lay out UI with anchors and containers, not absolute positions.
- The project uses the `mobile` renderer, the `Mobile` feature tag, and handheld orientation `5` (sensor portrait). Use touch input, e.g. `TouchScreenButton` as in `gameplay_scene.tscn`.

## Structure

Code is organized by module. Each scene lives next to the scripts it uses, and the project root holds no scripts:
- `menu/`: the main menu (`screen_main_menu.tscn`, `menu_buttons.gd`). `menu_button_sound.gd` (`class_name MainMenuButton extends Button`) is unfinished: `play_sound()` has no body, so the script fails to parse, and no scene uses it yet. `button_container.gd` is an empty editor template.
- `settings/`: the settings screen, the rhythm calibration screen (`screen_calibration.tscn`, `calibration_screen.gd`) and the `AudioSettings` autoload (`audio_settings.gd`).
- `song_select/`: the song select screen and its `song_card.tscn` rows.
- `songs/`: song and chart data shared by several modules: `SongInfo`, `SongLibrary`, `MidiFile`, `ChartMapper`, `TempoMap`, `Chart`. These are code modules; the song files themselves live in `Assets/Songs/`.
- `game/`: `gameplay_scene.tscn` and `gameplay.gd` (the game world), `song_player.gd`, `lane_note.gd`, `dancer.gd`, `health.gd`.
- `hud/`: `hud.tscn`, the shared HUD for every song, instanced inside `gameplay_scene.tscn`. `lane.tscn` (`LaneColumn`) is one lane: a colored strip, its brain `TouchScreenButton` and the notes that fall in it. For testing on a PC each lane also has a physical `key` (D, F, J, K, set in `hud.tscn`). Holding the key acts like holding the button (it swaps in the pressed texture and counts for `is_pressed()`), and pausing releases it. The calibration screen also accepts those keys or the space bar. `pause_button.gd` draws the pause icon. `pause_menu.tscn` (`PauseMenu`) is the pause overlay (`process_mode` Always) and only emits `resumed`/`retried`/`quit`; the HUD re-emits them as `*_requested` for `gameplay.gd`. It doubles as the game over screen (`show_game_over()`: title "MORISTE", no CONTINUAR). `health_bar.gd` (`HealthBar`) draws the health bar at the top.
- `results/`: the end-of-song screen (`screen_results.tscn`, `results_screen.gd`) and `SongResult` (`song_result.gd`), the stats of a play.
- `tools/`: command-line scripts that don't run inside the game (`midi_to_chart.gd`, `audio_to_lead_mid.py`).

Assets are organized by type under `Assets/`:
- `Assets/Images/Buttons/`: brain buttons in four colors (blue/green/red/yellow), each with a `_pressed` variant. These are probably the rhythm or dance input buttons. All of them are 480×480 with the brain in the same position. The pressed variant adds a glow in the padding. Keep new variants pixel-aligned, because `TouchScreenButton` draws from the top-left corner. Use a `shape` on the button so the touch area covers only the brain.
- `Assets/Images/Zombie/`: `zombie_frame_1..6.png`, 480×600 poses on the same canvas: 1 idle, 2 hand on face, 3 walking, 4 arms out, 5 kick with an arm up to the right, 6 pointing up to the left (disco). The background dancer uses them.
- `Assets/Fonts/ghost_shadow/`: the title and menu font. It has no glyphs for accented letters such as `Ú` or for arrows such as `▲`, so player-facing text is written in uppercase without accents. Lowercase can draw nothing at all (a lowercase `x` renders blank), which is another reason to use uppercase. Its glyphs are also drawn taller than the line height it reports. That's why the button styles use `content_margin_top = 40`, and why stacked labels need extra separation so they don't overlap.
- `Assets/configs/buttons/`: shared `StyleBox` `.tres` resources for the menu buttons' normal, hover, and pressed states. Reuse these resources for new menu buttons instead of creating inline styles.
- `Assets/Audio/audio perron/`: the button-press SFX (`.wav`). The `Plant Night Lullaby` music was a corrupt `.m4a` and was removed; it still needs to be added as `.ogg` (Godot can't import `.m4a`). `default_bus_layout.tres` defines the audio buses `MenuMusic`, `GameMusic`, and `Effects` (all routed to `Master`). Assign players to the matching bus.


Scene flow so far: `screen_main_menu.tscn` → `screen_song_select.tscn` → `gameplay_scene.tscn` → `screen_results.tscn` (CANCIONES → song select, REINTENTAR → gameplay), or menu → `screen_settings.tscn` → `screen_calibration.tscn` (AJUSTAR RITMO). VOLVER and the Android back gesture return to the menu. In gameplay, the back gesture pauses instead, or resumes when the pause menu is already open.
- **Menu:** `menu_buttons.gd` is attached to `button_container` and handles all three menu buttons. JUGAR and CONFIGURACION call `change_scene_to_file`, and SALIR calls `quit()`.
- **Song select:** `SongLibrary` (`song_library.gd`, static) scans `res://Assets/Songs/` with `ResourceLoader.list_directory()`. Each song is a folder with a `song.json` (`title`, `artist`, `difficulty` 1–10, `audio` file name, optional `cover`, optional `lead`, optional `offset`) plus its audio. `lead` is the original melody as a separate stem (e.g. split with Demucs); in that case `audio` is the backing track without the melody. `SongPlayer` (`game/song_player.gd`, an `AudioStreamPlayer` on `GameMusic`) plays both in sync through an `AudioStreamSynchronized`; `set_lead_muted()` fades the melody out on a miss and back in on a hit. `play_song(song, lead_in)` waits `lead_in` seconds before starting. `song_time()` is the clock for everything timed: it's negative during the wait, latency-compensated (`latency()` = `AudioServer.get_output_latency()` plus the player's `AudioSettings.latency_ms`, because on Android Godot barely reports the output latency and the sound comes out late), and smoothed (it runs on `Time.get_ticks_usec()` and slowly follows the audio position, because Godot's raw playback position jitters by ±20 ms and the notes would shake). Without `lead`, `audio` is the full song and misses aren't heard. The duration is not stored; it comes from `AudioStream.get_length()`. Folders with a bad JSON or missing audio are skipped with a warning. Each folder also has a `lead.mid` (a MIDI containing only the lead melody) and the `chart.json` generated from it. `chart.json` (version 4, read by `Chart`) holds `{version, source, tempo: [{time, beat, bpm}], notes: [{time, length, pitch, lane, beat, subdivision, group, hold, type?}]}`. The optional `type` is `"hostile"` or `"ghost"` (`Chart.NoteType`, names in `Chart.TYPE_NAMES`); a note without it is normal, so older v4 charts still load. Unknown types load as normal with a warning. `time` is in seconds and `beat` in quarter notes; `TempoMap` converts between them. `hold` is how many beats a hold note is held (0 for a tap); `Chart` adds `end_beat` and `end_time` to every note. Older charts are rejected with a warning, so re-run the converter. The MIDI's time 0 is taken as the start of the audio, so any lead-in silence in the audio belongs in the optional `offset` (seconds) in `song.json`. The gameplay reads note times as `song_time() - offset` (`_chart_time()`), so a positive offset makes the notes later. Use it to fine-tune a chart by ear. `song_select.gd` sorts by difficulty, name, artist or duration (tapping the same button again reverses the order) and instantiates `song_card.tscn` rows at runtime; their `pressed` signal is connected in code, the rest in the `.tscn`. The chosen song is stored in `SongLibrary.selected_song` (a static var, so it survives the scene change) for `gameplay_scene` to read. When exporting, add `*.json` to the preset's "non-resource files" filter or the `song.json` files won't be included in the `.pck`.
- **Charts (MIDI → lanes):** `MidiFile` (`midi_file.gd`) is a dependency-free parser for Standard MIDI Files (formats 0 and 1, tempo map, running status). Each note keeps its `channel` (0–15). Notes on DAW channel 2 are hostile and on channel 3 ghost (`ChartMapper.CHANNEL_TYPES`, counted from 1); every other channel is the melody. `ChartMapper` (`chart_mapper.gd`) assigns 4 lanes, left to right `Lane { GREEN, RED, YELLOW, BLUE }`, with higher notes further right. Chords collapse to their highest note. The melody is split into phrases at rests of 1 beat or more, or every 4 bars, and each phrase is normalized over at least 7 semitones. The lane never moves against the melody: repeated notes stay in the same lane, small steps may stay in the same lane, a leap of 3 or more semitones moves at least 1 lane, and an octave moves at least 2 lanes. Notes are then grouped the way they're beamed in sheet music. The eighths, triplet or sixteenths of one beat form a figure: one multi-hit note in the game, with `subdivision` 2, 3 or 4 (the coarsest grid all its notes fall on), sharing a `group` id and a lane. A note never has more than `MAX_FIGURE_HITS` (2) hits: a triplet becomes 2 + 1 and four sixteenths 2 + 2. A note alone in its beat (a quarter, a half note or a lone eighth) is a single note with `subdivision` 1. A lone note just before a figure (a pickup) is folded into that figure if the result stays on one grid with at most `MAX_FIGURE_HITS` (4) hits. Otherwise the two would sit about a quarter of a beat apart in the same lane and overlap. A note or figure that starts less than `LANE_CHANGE_BEATS` (0.5) after the previous note takes that note's lane, so two notes never land almost together in different lanes. The exception: the note after a multi-hit note (if it starts less than `SPREAD_BEATS`, 1 beat, later) and a multi-hit note right after another note always change lane (`_other_lane()`: its own lane if different, else one step in the melody's direction), so the same button isn't repeated and pieces of a split figure alternate lanes. Finally, a single note (`subdivision` 1) that sounds at least `HOLD_MIN_BEATS` (1) becomes a hold note: `hold` is its length rounded down to sixteenths and cut `HOLD_GAP_BEATS` (0.5) before the next note, and if that leaves less than `HOLD_MIN_BEATS` it stays a tap. Hostile and ghost notes are mapped apart from the melody (by phrase and pitch, no chord merging, never figures or holds), then `_place_traps()` moves each one to the nearest lane with no other note within `LANE_CHANGE_BEATS` (or under a hold); if every lane is busy it's dropped. `map()` sorts everything by time and renumbers `group` in order.
- **Settings:** `AudioSettings` (`audio_settings.gd`) is an autoload. At startup it loads each bus's volume (0–100) from `user://settings.cfg` and applies it; 0 mutes the bus. In `screen_settings.tscn`, each slider row uses `volume_row.gd` with an exported `bus_name`. Values are saved when you leave the screen. To add a slider for a new bus, duplicate a row and change `bus_name`. `AudioSettings.latency_ms` (−100 to 400, section `timing`) is the rhythm calibration. AJUSTAR RITMO opens the calibration screen: it plays a generated 80 BPM click through a `SongPlayer` with `use_calibration = false`, the player taps the brain on each click, and the median delay of their last 8 taps (after 4) becomes the latency. A slider fine-tunes it. It measures sound latency plus touch latency, so it also corrects taps.
- **Gameplay:** the root is a `Node2D` for the game world. The HUD is a separate scene (`hud/hud.tscn`) instanced as `HUD`; put touch controls, score, etc. there, not in `gameplay_scene.tscn`. Touch controls go under the HUD's `CanvasLayer` and use anchored `Control`s, e.g. `bottom_left`, so they stay at the screen edges with `aspect="expand"`. `gameplay.gd` plays a countdown (`cuenta_regresiva.wav` on `Effects`, with the on-screen numbers synced to the voice through `COUNTDOWN_CUES`), then the song. It spawns a `LaneNote` into the HUD lane a little before it should be visible. Notes don't slide: they all hop together on every integer beat of the song (Rift-style). Between hops each note rests at the height of the time it had left at its last hop (`LOOKAHEAD_BEATS` from top to button), and its final hop lands on the button exactly on its beat. `gameplay.gd` builds one `LaneNote` per chart `group`. A figure note has a white ring and the number of hits it has left, drawn by `_draw_badge()` in `lane_note.gd`. The plan is to replace that number with a custom icon per figure type (`hits[0].subdivision`). When you hit it, it is knocked back up the lane to the height of the time left until its next hit, capped at `KNOCK_HEIGHT` (0.5 beats) so it never reaches the next note in its lane, then comes down again. A missed hit also advances it (red flash), so the remaining hits stay playable. The lanes start dimmed (grey, and the buttons don't respond) and turn on with the "YA" only if the song has a chart; they dim again when no notes are left. Tapping a lane hits the earliest pending hit of that lane inside its window and unmutes the lead. The windows are graded by `JUDGEMENTS`: PERFECTO ≤ 60 ms, BIEN ≤ 120 ms, OK ≤ `HIT_WINDOW` (180 ms). Every grade counts as a hit, and `Hud.show_judgement()` pops it above the buttons. The late side is always `HIT_WINDOW`, but each note's `early` (`_assign_windows()`) never reaches back past the end of the previous hit in the same lane (with a minimum of `MIN_WINDOW`), so an extra tap right after a hit doesn't take the next one. Taps in a lane are consumed in order, so a player who is always a bit late still hits sixteenths. A hit that goes past its window is a miss (FALLO) and mutes the lead. **Trap notes:** hostile notes (dark purple with spikes and a red X, `_draw_hostile()`) and ghost notes (lane color at `GHOST_ALPHA`) don't count in `SongResult.total`. Pressing a lane with no normal hit in its window checks for a trap within `TRAP_WINDOW` (120 ms): a ghost is a regular miss, a hostile shows AUCH, counts a miss and calls `Health.hostile()`. Unpressed traps fade out (`pass_by()`) after `TRAP_WINDOW` with no penalty. `_group_hits()` groups by `group` id rather than adjacency (a trap can fall between two hits of a figure) and also caps notes at 2 hits for hand-edited charts. **Health:** `Health` (`health.gd`, a node in `gameplay_scene.tscn`, values are `@export`s tuned in the inspector) starts at `start_health` (50 of 100). A miss takes `miss_damage` plus `miss_streak_damage` per consecutive miss (capped), a hit heals `hit_heal` plus `streak_heal` per consecutive hit (capped). `hostile_punishment` is `INSTANT_DEATH` or `NEAR_DEATH` (default): health drops to what the next `hostile_misses_left` (3) misses would take, or by one miss if already lower. Its `changed` signal goes to `Hud.show_health()` and `died` to `gameplay.gd`, which pauses the tree and shows the game over menu (back gesture goes to song select). A missed hold head counts two misses but only damages once. **Hold notes:** a `LaneNote` with `hold` > 0 draws a tail upward to its `end_beat`, and the tail's end hops like any other note. Hitting the head starts the hold: the head stays on the button and the tail shortens until the end. `_update_holds()` polls `Hud.is_lane_pressed()` (the `TouchScreenButton`'s `is_pressed()`, so pausing also releases it). Reaching `end_time` with the finger down, or releasing at most `RELEASE_WINDOW` (150 ms) early, counts a second hit. Releasing earlier is a miss, and missing the head counts two misses. That's why `SongResult.total` is notes + holds. While a note is held the dancer keeps its pose (`Dancer.keep_pose()`). Every hit and miss is counted in a `SongResult` (hits, misses, combo); trap presses count as misses. The countdown voice also starts `SongPlayer.latency()` early so it's heard on time. The current combo shows at the top left of the HUD as `X23` (`Hud.show_combo()`): it pops on each hit and hides at 0. Its Ghost Shadow glyphs rise well above the label (about 70 px), which is why the `combo` box sits 190 px from the top, below the health bar (70–120 px). **Pause:** the HUD's pause button, the back gesture or the app going to the background (`NOTIFICATION_APPLICATION_PAUSED`) set `get_tree().paused`. The audio stops by itself, and `SongPlayer` freezes `song_time()` on `NOTIFICATION_PAUSED`/`UNPAUSED`, so the notes stay in sync. CONTINUAR runs a `RESUME_COUNT` 3-2-1 on the HUD countdown (timers that run while paused) before unpausing, REINTENTAR reloads the scene, and SALIR goes to the song select. Always unpause before changing scenes. **End:** when `SongPlayer` emits `finished`, gameplay waits `END_DELAY`, stores the result in `SongResult.last` (static, like `selected_song`) and opens the results screen. That screen shows the rank (S only with no misses, then A ≥ 90%, B ≥ 75%, C ≥ 60%, D), hits, misses, accuracy and max combo. **Dancer:** `Dancer` (`dancer.gd`, a `TextureRect` in the `Background` layer, behind the lanes and at 70% opacity) is the zombie dancing in the background. `gameplay.gd` calls `pose(lane)` on every lane press, hit or not. It shows that lane's pose for `POSE_TIME` with a small pop, then goes back to `idle`. The poses are exported in lane order: green = frame 6 (left), red = frame 4, yellow = frame 2 (a placeholder until there's a proper pose), blue = frame 5 (right). Opening the scene directly (without the song select) plays the first song that has a chart. `Assets/Songs/prueba_ritmo/` is a generated test song: a click track as `audio`, beeps on each note as `lead`, one section per figure, a tempo change from 120 to 90 BPM, and hostile/ghost notes (MIDI channels 2 and 3) in the first 40 beats.

Scene paths are hardcoded `res://` strings (`*_SCENE` constants in the scripts, the autoload in `project.godot`, `SongLibrary.SONGS_DIR`), so update them if you move files. Moving a `.gd` without its `.gd.uid` breaks the `uid://` references.

## Godot file conventions

- `.tscn`/`.tres` files reference resources by both `uid://` and `res://` path. Each `.gd` has a companion `.gd.uid` file, and each imported asset has a `.import` file. Commit these companion files, and move or rename them together with their source files (preferably through the editor) so UIDs don't break.
- Signal connections are declared in the `.tscn` (`[connection ...]` sections), not in code. Check the scene file when tracing handlers.
- `.godot/` (the import cache) and `/android/` are gitignored. Line endings are normalized to LF (`.gitattributes`).
